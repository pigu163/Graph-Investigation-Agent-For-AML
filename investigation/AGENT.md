# 单 Agent 按需调查（开发版）

这个版本从 PostgreSQL 的 `transactions` 表读取已存储的交易。Kafka 和 Flink 可以停止，PostgreSQL 必须运行并包含数据。它使用 LangGraph 编排调查，当前不是完整的自动化案件系统。

## 运行前准备

1. 使用项目的 Python 环境，安装 `pyproject.toml` 中的依赖。
2. 在项目根目录的 `.env` 中配置 `DS_key`；文件已经被 Git 忽略。不要把密钥写入代码或命令行。
3. 设置 PostgreSQL 标准环境变量 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`。请使用包含需要调查的交易的数据库。
4. 使用实际存在的 dataset、bank、account 和时间范围。IBM 数据源的事件时间没有时区，因此传入不含时区的时间；范围是左闭右开 `[start, end)`。

```bash
.venv/bin/python -m graph_investigation_agent_for_aml.agent.cli \
  --dataset graph-investigation --bank 01 --account A \
  --start 2022-09-01T09:00:00 --end 2022-09-01T10:00:00 \
  --question 'Investigate concentrated incoming transfers and rapid onward payments.' \
  --output report.json
```

不带 `--output` 时报告打印到终端。报告仍会在失败或预算耗尽时输出：退出码 `0` 表示 Agent 正常结束，`1` 表示模型、工具或证据校验失败，`2` 表示预算耗尽而未正常结束。默认输出 JSON；添加 `--format markdown` 可输出带账户统计、假设状态和已核验交易明细的可读报告。Markdown 最多列出 20 条交易，完整证据请使用 JSON 输出。输出包含原始交易证据，请按数据敏感程度保管。默认使用 DeepSeek 的 `deepseek-flash`，通过 `--model <模型ID>` 可以明确指定其他 DeepSeek 模型。DeepSeek 使用可能产生费用；默认每次运行最多请求模型 3 次，可以通过 `--max-model-calls` 显式设置上限（最多 10 次）。达到上限会标记 `model_budget_exhausted`。模型请求失败时报告保留已有证据。

## 固定流程对照

在上述命令后加 `--compare-baseline`，会在同一数据库快照和相同工具、时间预算下，额外运行账户概况 → 交易 → 扩图 → fan-in → 快速转出的固定流程。报告的 `comparison` 包含两边的假设状态、交易 ID、工具调用次数、用时及证据校验错误。`tests/fixtures/agent-cases.json` 提供半份合成交易中四个账户的指标与证据标注，`score_case` 可评估报告的指标判断和证据引用；未检查或因截断而无法判断的结果不计为正确或错误。这些标签仅用于评估，不会传给 Agent。人工标注的合成指标不代表金融犯罪。模型的 token 用量仅汇总供应商实际返回的 usage，无法从调用次数推算账单。

## LangGraph 如何运行

`agent/state.py` 定义一次调查共享的数据；每次工具执行后，程序根据已核验的证据更新集中收款和快速转出两项假设状态，下一次模型决策会看到这些状态。`agent/graph.py` 创建三个节点：

1. `plan` 先要求程序取得账户概况和交易明细，然后把已有结果和允许调用的工具交给模型选择下一步。
2. `tool` 使用目标账户和时间范围执行预定义函数，把真实结果和状态放回共享状态。图扩展、查询条数及数据库语句均有限制。
3. 条件边判断继续调用工具还是进入 `report`。工具执行后返回 `plan`，形成循环；到达工具、模型或时间预算，或者发生模型错误时停止。
4. `report` 原样保存工具产生的证据和实际动作，并核对图分析结果中的交易 ID、时间、方向和金额字段是否与扩图结果一致；对于快速转出和双向交易，还重新计算交易对的时间差及金额比较；不一致的发现不会进入通过校验的发现列表。它还会列出未执行的关键分析。模型生成的工具调用目的属于调查意图，不是已经验证的事实。

完整的工具输出不会被模型的摘要替换。报告中的金额、交易和路径直接来自分析工具；图分析本身不证明同一笔资金移动或犯罪事实。具体工具语义见本目录的 README。

## 当前限制

- 这是首版 CLI：没有 FastAPI、持久化案件状态、报告叙述生成或人工审批。
- 输出包含由工具结果生成的摘要、结构化证据和调查建议；Markdown 报告采用固定模板，不包含模型生成的自由叙述。交易字段校验针对同一次扩图结果，不能代替独立来源核验。结果依赖模型实际选择的工具；未执行的工具不代表无异常。
- 可以添加 `--as-of 2026-10-30T12:00:00+00:00`，只读取该时刻或之前已经写入 PostgreSQL 的交易（按照 `stored_at`）。这不重建真实世界的历史可得性：历史 CSV 在今天重放时，入库时间是今天，而不是原交易发生的日期。没有来源系统的历史可得时间时，不能据此声称回测没有未来信息泄漏。固定流程对照已提供；测试集包含四个人工标注的合成账户案例，已进行一次小规模真实模型对照，但不能据此推断实际场景中的模型效果。详见 [评估记录](EVALUATION.md)。
- 时间预算在节点之间检查；模型请求和数据库语句的超时不超过各自上限或当时剩余预算。Python 计算、连接建立和系统调度仍可能使总耗时超过预算，因此不是严格的整体墙钟时间上限。
- 模型会收到本次案件参数和工具结果。只应发送你有权交给所选模型服务商处理的数据。报告记录截断和工具失败；查询源数据完整性仍需另行确认。
